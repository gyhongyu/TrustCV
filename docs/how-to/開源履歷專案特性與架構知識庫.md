# 開源履歷專案特性與架構知識庫 (Open-Source Resume Benchmarks Knowledge Base)

本文件為純技術與架構參考知識庫（Reference Manual），專供 AI 開發代理（Coding Agent）與工程師查閱。內容深入剖析當前主流開源履歷專案的系統設計、UI/UX 互動模式、資料結構規範與能力邊界，作為系統設計時的特性對照與模式參考。

---

## 1. 專案特性深度剖析 (Deep Dive)

### 1.1 Reactive Resume
* **GitHub Repository**: `reactive-resume/reactive-resume`
* **開源協議**: MIT License（無商業限制、無功能付費牆）
* **定位**: 現代化、全功能、所見即所得（WYSIWYG）的履歷建置與排版系統。

#### 技術棧架構
* **前端**: React, Vite, Tailwind CSS, shadcn/ui, Zustand / Redux (狀態管理)
* **渲染引擎**: 瀏覽器端向量渲染 (`@react-pdf/renderer`)
* **後端**: NestJS, PostgreSQL, Prisma ORM, Redis (快取與隊列), MinIO / S3 (附件與頭像儲存)
* **國際化**: 完整支援 i18n 多國語言

#### UI/UX 互動模式
* **雙欄工作台 (Split-view Canvas)**：
  * 左側為資料輸入區，右側為等比縮放的即時 A4 畫布。任何文字或樣式變更均具備即時反應能力。
* **模組化抽屜 (Modular Drawer System)**：
  * 每種履歷段落（工作經驗、學歷、技能、自訂區塊等）均為獨立模組。
  * 支援區塊開關（Visibility Toggle）與拖曳排序（Drag & Drop Reordering）。
* **單/雙欄版面動態分配 (Column Layout Switching)**：
  * 支援將特定模組配置到主欄（Main Column）或側邊欄（Sidebar）。

#### 排版與自定義能力
* **內建模板**: 提供 15+ 種預設樣式模板。
* **排版參數**: 支援字型（Google Fonts 整合）、字號階層、行高、頁邊距及色彩主題（Primary, Background, Text）即時調色盤。
* **自訂樣式**: 支援 Custom CSS 注入，允許覆寫底層樣式。
* **資料規範**: 嚴格遵循並延伸國際標準 `JSON Resume` Schema。

#### LLM / AI 能力邊界
* **定位**: 單行 / 單段輔助潤飾（AI Writing Assistant）。
* **功能**: 語法檢查、語氣轉換（Professional, Action-oriented）、翻譯、個人摘要生成。
* **限制**: 僅支援單檔文字操作，**不支援**多附件非結構化資產提取，亦**無**跨文件去重與知識庫概念。

### 1.2 OpenResume
* **GitHub Repository**: `xitanggg/open-resume`
* **開源協議**: MIT License
* **定位**: 專注於隱私、極度輕量、純前端運行的 ATS 友善履歷編輯與 PDF 解析工具。

#### 技術棧架構
* **核心框架**: Next.js (React), Tailwind CSS
* **後端 / 資料庫**: **零後端（Client-side only）**，不依賴後端伺服器與資料庫，資料直接留存於瀏覽器 LocalStorage
* **PDF 解析與渲染**: `pdfjs-dist` (文字層抓取) + `@react-pdf/renderer` (瀏覽器端 PDF 輸出)

#### UI/UX 核心亮點：稽核與比對視窗 (Parser Inspector)
* **文字與表單即時對照 (Dual-pane Audit View)**：
  * 使用者匯入舊 PDF 履歷後，系統提供核對介面：左側為解析後的結構化欄位，右側同步標記原始檔案對應的文字區域。
  * 若欄位辨識信心度不足（例如時間格式不明確），會以警告標籤醒目提示，由使用者進行人工確認。

#### 排版與自定義能力
* **模板策略**: 專注於通過歐美企業 ATS（Applicant Tracking System）自動篩選，僅提供 1 套標準單欄 ATS 格式。
* **微調項目**: 僅開放強調色（Accent Color）、字體大小（Small / Medium / Large）、頁邊距（Margin）與 3~4 種無襯線/襯線字體切換。
* **限制**: 不支援雙欄排版、不支援 Custom CSS、無多模板切換。

#### LLM / AI 能力邊界
* **零 AI 整合**: 完全不使用 LLM 或神經網路模型。
* **解析機制**: 採用純前端正規表達式（RegEx）與字串特徵啟發式演算法（Heuristic text parsing）。

### 1.3 ResumeLM
* **GitHub Repository**: `olyaiy/resume-lm`
* **開源協議**: MIT License
* **定位**: 針對特定職缺描述（Job Description, JD）進行動態匹配與客製化的 AI 履歷生成器。

#### 技術棧架構
* **核心框架**: Next.js App Router (React Server Components), TypeScript
* **UI 組件庫**: Tailwind CSS, shadcn/ui, Radix UI
* **後端 / 儲存**: Supabase (PostgreSQL + Auth)
* **LLM 串接**: Vercel AI SDK，支援主流大模型（OpenAI, Claude 等）

#### UI/UX 核心亮點：AI 審批與多變體管理 (Approval Workflow)
* **母庫與衍生版解耦 (Master Profile vs. Variants)**：
  * **Base Profile（母庫）**：儲存個人 100% 的完整學經歷與技能全集。
  * **Job-Specific Variant（職缺特化版）**：針對特定 JD，AI 自動挑選最相關的專案與技能重新組合。
* **行級 AI 審批機制 (Inline Review System)**：
  * 每條工作經歷（Bullet Point）經 LLM 優化或重寫後，介面提供 `[Accept]`, `[Regenerate]`, `[Revert]` 三態控制按鈕，讓使用者保留最終裁量權。

#### 排版與自定義能力
* **設計風格**: 現代科技簡約風（Clean / Minimalist ATS-friendly）。
* **自定義彈性**: 支援標準字型、間距微調與區塊排序，主要聚焦於內容與職缺關鍵字的匹配度，而非視覺外觀的多樣化。

#### LLM / AI 能力邊界
* **定位**: 職缺關鍵字提取、量化成果重寫、ATS 匹配評分。
* **限制**: 假設使用者已有文字基礎，**不包含** OCR 影像識別與多檔案憑證整理管線。

## 2. 三大專案核心維度橫向對照矩陣

| 比較維度 | Reactive Resume | OpenResume | ResumeLM |
| :--- | :--- | :--- | :--- |
| **開源協議** | MIT | MIT | MIT |
| **系統架構複雜度** | 高（微服務/多容器：NestJS + PG + MinIO + Redis） | 極低（純前端靜態部署，無資料庫） | 中等（Next.js App Router + Supabase） |
| **資料標準** | JSON Resume 標準結構 | 自定義輕量 Profile 結構 | 結構化 Profile + JD 對照實體 |
| **即時預覽技術** | `@react-pdf/renderer` (動態畫布) | `@react-pdf/renderer` | 響應式 HTML 預覽 + PDF 匯出 |
| **排版客製彈性** | ★★★★★ (15+ 主題, CSS 注入, 雙欄) | ★★☆☆☆ (僅 1 套固定單欄 ATS) | ★★★☆☆ (現代科技簡約 ATS 風格) |
| **AI 介入深度** | 輔助潤飾（行內改寫、翻譯、拼寫） | 無（純正規表達式 Rule-based） | 職缺客製（JD 分析、Bullet Points 優化） |
| **多檔案素材庫** | ❌ 僅單一現有簡歷匯入 | ❌ 僅單一 PDF 解析 | ❌ 需手動輸入或貼上文字 |
| **資料核對機制** | 即時表單反饋 | 雙視窗原文高亮對照 (Parser Inspector) | 每條經歷 Approve / Reject 審批機制 |

## 3. 開源設計模式庫 (Design Patterns for Reference)

本節彙整三個專案中最具借鑑價值的四大架構與互動模式，供系統設計時參考：

### 模式 A：即時向量渲染畫布模式 (Live Vector Canvas Pattern)
* **來源**: *Reactive Resume* / *OpenResume*
* **原理**: 捨棄後端 Puppeteer 無頭瀏覽器截圖的高資源消耗做法，改在前端利用 `@react-pdf/renderer` 的 `PDFViewer` 或自定義虛擬 DOM 容器進行繪製。
* **特點**:
  * 支援非同步排版運算，不阻塞主線程輸入。
  * 匯出時所見即所得，維持向量字型與超連結完整性。

### 模式 B：萃取溯源與核對檢視模式 (Audit & Inspector Pattern)
* **來源**: *OpenResume*
* **原理**: 在結構化資料與原始檔案之間建立雙向索引映射（Two-way Data Mapping）。
* **特點**:
  * 當使用者檢視提取出的欄位（例如：證照名稱、發證時間）時，介面可連動提示原始文件中的文字段落或頁碼。
  * 解決使用者對自動提取技術產生的「幻覺恐懼」與「遺漏焦慮」。

### 模式 C：母庫與衍生版分層架構 (Master-Variant Decoupling Pattern)
* **來源**: *ResumeLM*
* **原理**: 將「個人全量經歷資料庫」與「目標履歷」分離為兩層資料實體。
* **特點**:
  * **Master Profile (母資料)**：唯讀或高可信度資產，包含所有歷史專案、證書、技能標籤。
  * **Target Variant (職缺衍生版)**：視不同應徵場景（如顧問職、技術主管職）動態組裝衍生，不污染母資料庫。

### 模式 D：行級審批反饋架構 (Granular Approval Loop Pattern)
* **來源**: *ResumeLM*
* **原理**: AI 針對內容的修改不採用「整篇替換」或「黑盒輸出」，而是拆解為最小單元（Atomic Bullet Points）。
* **特點**:
  * 提供局部操作：`[保留原樣]`、`[接受優化]`、`[重新生成]`。
  * 賦予使用者對內容的最終掌控權，提升人機協同編輯的信任度。
